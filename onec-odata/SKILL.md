# 1С OData

- Доступ к данным базы 1С через стандартный интерфейс OData версии 3: `<сервер>/<публикация>/odata/standard.odata`.
- Все запросы - через `scripts/odata.sh` из каталога этого skill (путь к каталогу указан при загрузке skill). Скрипт работает в Linux, macOS и Git Bash под Windows, нужны только `bash` и `curl`.
- Идентификатор снимка метаданных (аргумент skill): $ARGUMENTS. Это непрозрачная строка: сменилась - кеш описания сервиса устарел. Если не передан - определи по CLAUDE.md проекта; если и там не сказано - работай без него. Передавай его в каждом вызове скрипта ключом `--snapshot-id`, при смене скрипт сам скачает кеш заново.
- Скрипт сам кодирует URL: ресурс и выражения передаются как есть, с кириллицей, пробелами и `$`. Пароль берется из профиля и не попадает ни в команду, ни в вывод.
- По умолчанию работа **только на чтение**. Любое изменение данных - по `references/write-operations.md` и только после явного согласия пользователя на конкретный запрос.

Читай нужный файл по мере работы:

| Когда нужен | Что делать |
| --- | --- |
| Имя ресурса, суффиксы `_Key`/`_Type`/`____Presentation`, стандартные реквизиты, ключи регистров, типы | Читай `references/naming.md` |
| Пишешь `$filter`: операторы, функции, составные реквизиты, `any`/`all` | Читай `references/filter.md` |
| `$select`, `$expand`, `$top`/`$skip`, `$count`, `$inlinecount`, `$orderby`, `allowedOnly`, `$format` | Читай `references/query-options.md` |
| Остатки, обороты, срезы, наборы записей регистра по регистратору | Читай `references/virtual-tables.md` |
| Ответ с HTTP 4xx/5xx, внутренний код ошибки, стенд не отвечает | Читай `references/errors.md` |

## Профиль подключения

Профиль - env-файл с адресом и учетными данными базы. Лежит в `.onec-odata/<имя>.env` в корне репозитория проекта, каталог исключен из git. Скрипт ищет профиль сам от текущего каталога, поэтому запускай его из каталога проекта. Настройка профилей - в `README.md` репозитория skill.

- Имя профиля возьми из CLAUDE.md проекта. Если там не указано - спроси пользователя, не перебирай и не читай файлы профилей: в них пароли.
- Профиль не найден или скрипт отказался его читать (не исключен из git) - сообщи пользователю, не создавай профиль сам.
- В начале работы выполни `info`: покажет адрес публикации (без пароля) и проверит доступ.
- В ответах о данных называй базу (публикацию), из которой они получены.

## Команды

```bash
S=<каталог skill>/scripts/odata.sh
bash $S -p ut info                                   # адрес, пользователь, число опубликованных наборов
bash $S -p ut sets 'Перемещение'                     # поиск наборов сущностей по регулярному выражению
bash $S -p ut meta Document_ПеремещениеТоваров       # ключи, свойства, навигация, функции типа
bash $S -p ut get Document_ПеремещениеТоваров \
  --filter "Date ge datetime'2025-07-01T00:00:00' and Posted eq true" \
  --select "Ref_Key,Number,Date,Организация____Presentation" --top 5
bash $S -p ut count Document_ПеремещениеТоваров --filter "Posted eq false"
bash $S -p ut link Document_ПеремещениеТоваров 7a3c9e15-4e91-11f0-8b2d-0050568a1f42   # ссылка на объект
```

Опции `get`: `--filter`, `--select`, `--expand`, `--orderby`, `--top`, `--skip`, `--inlinecount`, `--allowed-only`, `--param ИМЯ=ЗНАЧЕНИЕ`, `--meta none|minimal|full`, `--xml`, `--out ФАЙЛ`, `--max-print БАЙТ`. Полная справка: `bash $S help`.

Что видишь в выводе:

- в stderr - строка `HTTP <код> | <время> | <размер> | <метод> <URL>`, URL в раскодированном виде;
- при коде 4xx/5xx - тело ошибки целиком (`m:code`, `m:message`) и код выхода 1: причина видна сразу, повторять запрос не нужно;
- тело больше `--max-print` (20000 байт) сохраняется в файл, в вывод идет начало и путь к файлу. Нужное ищи в файле поиском, а не чтением целиком. Файл результата временный: когда нужное из него взято, удали его.

`sets` и `meta` работают по кешу описания сервиса (`$metadata` - десятки МБ, качается один раз). С идентификатором снимка кеш обновляется сам: `bash $S -p <профиль> --snapshot-id <ИД> ...`. Без него - только через `meta ИМЯ --refresh`.

## Порядок работы

1. **Имя набора** - `sets` по фрагменту имени объекта. Имя строится как `Префикс_ИмяОбъекта[_Суффикс]`: `Document_ЗаказПокупателя`, `Document_ЗаказПокупателя_Товары`, `AccumulationRegister_ТоварыНаСкладах_RecordType`.
2. **Имена и типы реквизитов** - `meta` по типу. Не угадывай имя реквизита и форму литерала, бери из `meta`: `Edm.Guid` - ссылка, `Edm.String` вместе со свойством `<Имя>_Type` - составной реквизит.
3. **Запрос** - `get` с отбором и узким `--select`. Наименования ссылок получай полем `<Реквизит>____Presentation` в том же запросе, а не отдельными запросами к справочникам.
4. **Количество** - `count` или `--inlinecount` с `--top 1`: распределение считается без выгрузки данных.

## Литералы в отборе

Главная ловушка: **неверная форма литерала не дает ошибки**. Запрос отрабатывает с HTTP 200 и возвращает пустой результат или 0, внешне неотличимо от «таких данных нет». Опечатка в имени реквизита, наоборот, дает ошибку («Сегмент пути X не найден»), как и несуществующее значение перечисления.

| Что сравниваешь | Как писать | Неверно (молча пусто) |
| --- | --- | --- |
| ссылочный реквизит | `Организация_Key eq guid'bd10887b-...'` | `Организация_Key eq 'bd10887b-...'` |
| ссылка через навигацию | `Организация/Ref_Key eq guid'...'` | - |
| составной реквизит (в том числе `Recorder`) | `Recorder eq cast(guid'...', 'Document_ПеремещениеТоваров')` | `Recorder eq '...'`, `Recorder eq guid'...'` дает ошибку |
| тип составного реквизита | `isof(ДокументОснование, 'Document_ЗаказПокупателя')` или `ДокументОснование_Type eq 'StandardODATA.Document_ЗаказПокупателя'` | - |
| перечисление | `ВидОперации eq 'ТоварыПродукция'` (имя значения) | - |
| дата | `Date ge datetime'2025-07-01T00:00:00'` | `Date ge '2025-07-01'` |
| булево, число | `Posted eq true`, `Количество gt 10` | - |
| строка | `Number eq 'ПТ00000123'` | - |

У составного реквизита, заполненного **пустой ссылкой** конкретного типа, `_Type` содержит этот тип, а значение - GUID из нулей. Поэтому `X_Type ne 'StandardODATA.Undefined'` не значит «реквизит заполнен».

Подробности и функции - `references/filter.md`.

## Прежде чем сказать «таких данных нет»

Пустой результат сам по себе ничего не доказывает. Нужны два подтверждения:

1. тот же отбор на **заведомо непустом** значении возвращает записи - значит, форма отбора верна;
2. `count` или `--inlinecount` по своему отбору показывает 0.

## Медленные выборки

Выборка без отбора из некоторых регистров идет десятки секунд даже с `--top 3`, а с отбором по ссылке - доли секунды. Заранее это не определить: время зависит не от размера таблицы, а от того, как платформа строит запрос (замер на 8.3.16: регистр на 44 млн записей отдал `--top 3` за 0,05 с, регистры на 2-4 млн - за 35-40 с). `count` без отбора быстрый везде и медленную таблицу не выдает.

- Первый запрос без отбора к незнакомой таблице - с коротким таймаутом: `ONEC_TIMEOUT=15 bash $S ...`. Не уложился (curl, код 28) - не повторяй с большим таймаутом, а добавь отбор.
- К регистру иди с отбором по конкретной ссылке. Ссылки нет - сначала найди ее в документах.
- Набор записей одного регистратора проще всего читать по каноническому ключу: `get "AccumulationRegister_X(Recorder='<guid>', Recorder_Type='StandardODATA.Document_Y')"` (см. `references/virtual-tables.md`).
- Если отбора по ссылке нет, ограничивай период: `Period ge datetime'...'`.

## Ссылки на объекты

Режим показывает `info` (строка «ссылки на объекты»), он задается в профиле:

- `off` - ссылок не давай;
- `on-request` - ссылку давай, когда пользователь просит, и всегда - на объект, измененный через `write`;
- `always` - давай ссылку на каждый объект (документ, элемент справочника и т. п.), который упоминаешь в ответе.

Ссылки получай командой `link`, не собирай вручную: `ref` - это GUID с переставленными группами. Навигационную ссылку 1С показывай кодом (`e1cib/data/...`, открывается в клиенте через «Перейти по ссылке»), ссылку веб-клиента - markdown-ссылкой с номером или наименованием объекта. Для записей регистров ссылки на запись нет, только на список регистра. Учетные данные в ссылку не добавляй (параметры `N` и `P` веб-клиента): пароль попал бы в историю браузера, журнал веб-сервера и переписку. Вход в клиент пользователь выполняет сам.

## Экономия контекста

- Всегда задавай `--select`: по умолчанию приходят все реквизиты и все табличные части. `--select "**"` - все реквизиты без табличных частей.
- Строки табличной части - через путь: `--select "Number,Товары/Номенклатура_Key,Товары/Количество"`.
- Служебные поля json по умолчанию отключены (`--meta none`), не включай их без нужды.
- OData не умеет соединений и агрегатов: сводные расчеты собирай несколькими узкими выборками.
