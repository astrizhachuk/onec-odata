# Изменение данных

Источник: «Руководство разработчика», раздел «Выполнение типовых операций» (8.3.16: 17.2.1.13; с 8.3.21: 17.4.13).

## Порядок согласования

Любой запрос, меняющий данные, - необратимое действие в чужой базе. Перед каждым:

1. Покажи пользователю базу (`info`), метод, ресурс, тело запроса и заголовки (`If-Match`, режим загрузки).
2. Дождись явного «да» именно на этот запрос. Согласие на один запрос не распространяется на следующий.
3. Выполни `write ... --confirmed`. Флаг означает «пользователь подтвердил», без подтверждения его не ставь.
4. Прочитай объект после записи и покажи результат.

Профиль с `ONEC_READONLY=1` запрещает `write` - не обходи это прямым curl.

```bash
bash $S -p ut write PATCH "Catalog_Товары(guid'<guid>')" --body /path/body.json --if-match '<DataVersion>' --confirmed
bash $S -p ut write POST "Document_РасходТоваров(guid'<guid>')/Post?PostingModeOperational=false" --confirmed
```

Тело готовь отдельным файлом (json, UTF-8), а не строкой в команде.

## Создание - POST на набор

`POST Catalog_Товары` с телом объекта. Свойства, которых нет у объекта, игнорируются. Ответ 201 и созданный объект с `Ref_Key`.

```json
{
  "Description": "Шлепанцы",
  "Parent_Key": "bbb079ae-8c51-11db-a9b0-00055d49b45e",
  "IsFolder": false,
  "Артикул": "SL56X",
  "Поставщик_Key": "086715b0-f348-11db-a9c5-00055d49b45e",
  "Вид": "Товар"
}
```

## Изменение - PATCH или PUT на канонический URL

- `PATCH` - меняются только переданные свойства.
- `PUT` - нужно передать все свойства объекта.
- Ссылочный реквизит в PUT - через `<Реквизит>@odata.bind` с URI сущности (можно укороченным, после `standard.odata/`): `"Организация@odata.bind": "Catalog_Организации(guid'...')"`.
- **Табличная часть передается целиком** - все строки, даже если меняется одна. Тип коллекции указывается `"<ТЧ>@odata.type": "Collection(StandardODATA.<Объект>_<ТЧ>_RowType)"`.
- Строки табличной части напрямую не создаются (код 13).

```json
{
  "Description": "Новое описание магазина",
  "ТорговыеЗалы@odata.type": "Collection(StandardODATA.Catalog_Магазины_ТорговыеЗалы_RowType)",
  "ТорговыеЗалы": [
    { "LineNumber": "1", "Название": "Синий зал", "Площадь": 56 },
    { "LineNumber": "2", "Название": "Красный зал", "Площадь": 56 }
  ]
}
```

Набор записей регистра: прочитать набор GET по регистратору, изменить, отправить PATCH на тот же адрес с заголовком типа:

```json
{
  "odata.type": "StandardODATA.AccountingRegister_X_RowType",
  "Recorder_Key": "<guid>",
  "RecordSet@odata.type": "Collection(StandardODATA.AccountingRegister_X_RowType)",
  "RecordSet": [ ]
}
```

Константа: `PATCH Constant_ИспользоватьИнтеграцию(guid'00000000-0000-0000-0000-000000000000')` с телом `{"Value": true}`.

## Удаление - DELETE на канонический URL

**Объект удаляется физически, пометка удаления не ставится.** Для пометки удаления - `PATCH` с `{"DeletionMark": true}`.

## Оптимистическая блокировка

Передай в `--if-match` значение `DataVersion`, прочитанное перед изменением. Если объект изменился - HTTP 412, действие не выполняется. Используй при любом PATCH, PUT и DELETE существующего объекта.

## Режим загрузки

`--load-mode` - заголовок `1C_OData-DataLoadMode: true`: запись как при обмене (`ОбменДанными.Загрузка = Истина`), без большинства проверок и обработчиков. Объект без поддержки режима - код 17.

## Действия

| Действие | Запрос |
| --- | --- |
| проведение документа | `POST Document_X(guid'...')/Post?PostingModeOperational=false` |
| отмена проведения | `POST Document_X(guid'...')/Unpost` |
| старт бизнес-процесса | `POST BusinessProcess_X(guid'...')/Start` (параметр `RoutePoint` - в `meta`) |
| выполнение задачи | `POST Task_X(guid'...')/ExecuteTask` |
| формирование сообщения обмена | `POST SelectChanges?DataExchangePoint='<URL узла плана обмена>'&MessageNo=34` |
| подтверждение получения изменений | `POST NotifyChangesReceived?DataExchangePoint='<URL узла>'&MessageNo=34` |

`SelectChanges` и `NotifyChangesReceived` меняют состояние регистрации изменений узла - это тоже изменение данных, даже если выглядит как чтение. Доступные действия типа видны в `meta` с пометкой `[изменяет данные]`.
