# Ошибки и диагностика

Источник: «Руководство разработчика», раздел «Ошибочные ситуации» (8.3.16: 17.2.1.10; с 8.3.21: 17.4.10), плюс наблюдения на стендах.

`odata.sh` при ответе 4xx/5xx печатает тело ошибки целиком и завершается с кодом 1. В json ошибка выглядит как `odata.error.code` / `odata.error.message.value`, в xml - `m:code` / `m:message`.

## Внутренние коды ошибок

| Код | Причина | Что обычно значит на практике |
| --- | --- | --- |
| 0 | возможность не поддерживается | например, `$expand` для одиночной сущности (HTTP 501) |
| 1 | не удалось разобрать строку | синтаксис литерала или выражения |
| 2 | неверный формат запроса | |
| 3 | запрошенный тип представления не поддерживается | значение `$format` |
| 4 | неверное значение свойства | в том числе несуществующее значение перечисления в отборе |
| 5 | отсутствует обязательное значение свойства | при записи |
| 6 | неверный URL | в том числе «Сегмент пути X не найден» - опечатка в имени реквизита или набора |
| 7 | не хватает элемента ключа сущности | указаны не все ключи (`meta` покажет `key`) |
| 8 | тип сущности не найден | набор не опубликован или имя неверно (`sets`) |
| 9 | экземпляр сущности не найден | нет объекта с таким ключом; у набора записей - нет движений |
| 10 | запрошенное свойство не найдено | |
| 11 | метод не найден | функция виртуальной таблицы недоступна для этого ресурса |
| 12 | отсутствует обязательный аргумент метода | |
| 13 | создание строк табличных частей напрямую не поддерживается | табличная часть пишется только в составе объекта |
| 14 | ошибка разбора опций запроса | |
| 15 | сущность с таким ключом уже существует | при создании |
| 16 | не удалось присвоить свойство | |
| 17 | объект не поддерживает режим загрузки данных | заголовок `1C_OData-DataLoadMode` |
| 18 | ошибка инициализации интерфейса OData: свойства с одинаковыми именами | дефект публикуемого состава |
| 19 | HTTP-метод запрещен в данном контексте | |
| 20 | ошибка прав доступа | нет прав или в выборку попала запись под RLS без `allowedOnly` |
| 21 | вызов нереализованной функции, неверное число или тип аргументов, нереализованная лямбда-функция | |

Ошибка выполнения запроса к базе (например, сравнение несовместимых полей) приходит с текстом сгенерированного запроса и позицией: `{(4, 85)}: Неверные параметры в операции сравнения. Нельзя сравнивать поля`.

## HTTP-статусы стенда

| Ответ | Причина |
| --- | --- |
| curl: код выхода 6/7/28, `HTTP 000` | сеть: имя стенда не разрешается, хост недоступен или таймаут; проверить VPN и DNS |
| 401 без учетных данных | публикация живая, ждет авторизацию |
| 401 с внутренним кодом 20 | права или RLS (см. `--allowed-only`) |
| 402 «Неверно указан пользователь или пароль» | такого пользователя нет в этой базе: учетные записи у каждой базы свои |
| 409 «Различаются версии клиента и сервера (<модуль> - <кластер>)» | модуль веб-сервера не той сборки, что кластер; по тексту видна сборка кластера |
| 412 | `If-Match` не совпал с `DataVersion`: объект изменен после чтения |
| 500 | ошибка на сервере; текст - в теле |
| 501 «Параметр не поддерживается» | неподдерживаемая опция; при ручном curl - часто `\$` вместо `%24` в URL |
| 200 и пустой `value` в корне сервиса | состав стандартного интерфейса не настроен (`publication.md`) |
| обрыв соединения по таймауту (curl, код 28) | медленная выборка без отбора (SKILL.md, «Медленные выборки»); таймаут меняется `ONEC_TIMEOUT` |

## Ручная проверка без скрипта

Если нужно воспроизвести запрос вне `odata.sh`, `$` в URL пиши как `%24`, кириллицу - в percent-encoding, учетные данные бери из того же профиля, а не в командной строке. Скрипт печатает раскодированный URL в строке `HTTP ...`, его можно взять за основу.
