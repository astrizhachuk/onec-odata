# Публикация и состав интерфейса

Источник: «Руководство разработчика», разделы «Установка значений разделителей» и «Публикация стандартного интерфейса OData» (8.3.16: 17.2.1.11-17.2.1.12; с 8.3.21: 17.4.11-17.4.12); описание `default.vrd` - «Руководство администратора».

Все действия ниже меняют настройки веб-сервера или данные базы. Агент их не выполняет: сообщи пользователю, что нужно сделать.

## Публикация на веб-сервере

- Публикуется через диалог конфигуратора «Администрирование - Публикация на веб-сервере»; в `default.vrd` появляется `<standardOdata enable="true" .../>`.
- Адрес сервиса: `<адрес публикации>/odata/standard.odata`. Адрес публикации - тот же, что для веб-клиента.
- Модуль веб-сервера должен совпадать по сборке с кластером 1С (иначе HTTP 409), по разрядности - с веб-сервером. Один процесс веб-сервера загружает модуль одной сборки, поэтому базы на кластерах разных сборок публикуются разными экземплярами веб-сервера.

## Состав стандартного интерфейса

Объект доступен через OData, только если он включен в состав стандартного интерфейса методом глобального контекста `УстановитьСоставСтандартногоИнтерфейсаOData()`. Состав хранится в самой базе, а не в `default.vrd` и не в конфигурации.

- Режим совместимости 8.3.4 и ниже: метод не используется, доступны **все** поддерживаемые объекты.
- Новее 8.3.4: доступно только включенное. Корень сервиса с `"value": []` - состав пуст. Набора нет в `sets` - объект не включен, а не «объекта нет в конфигурации».
- Способы задать состав (все вызывают этот метод в базе):
  - форма БСП «Настройки стандартного интерфейса OData» (раздел «Администрирование - Синхронизация данных») - в конфигурациях на БСП;
  - внешняя обработка;
  - внешнее соединение COM (`V83.COMConnector`), конфигурацию не меняет;
  - код в конфигурации или расширении (например, при обновлении информационной базы).

## Разделители

В базе с разделением данных значения разделителей задаются только фрагментом URL публикации или в `default.vrd`. Параметр `Z` командной строки не поддерживается.
