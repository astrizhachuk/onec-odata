# Параметры запроса

Источник: «Руководство разработчика», разделы «Параметры запроса», «Способы получения описания», «Способы получения данных» (8.3.16: 17.2.1.5-17.2.1.8; с 8.3.21: 17.4.5-17.4.8). В скобках - опция `odata.sh get`.

## $select (`--select`)

| Значение | Результат |
| --- | --- |
| не указан или `*` | все свойства, включая табличные части |
| `**` | все свойства, кроме табличных частей |
| `Ref_Key,Number,Date` | перечисленные свойства (с суффиксами: `Организация_Key`) |
| `Товары/Номенклатура_Key,Товары/Количество` | выбранные колонки табличной части; у набора записей регистра - `RecordSet/<Поле>` |
| `Организация____Presentation`, `Presentation` | представления (см. `naming.md`) |
| `Организация/ИНН` вместе с `$expand=Организация` | реквизиты связанной сущности |

При одновременных `Объект/*`, `Объект/**`, `Объект/Поле`: `*` включает все, иначе `**` включает все без табличных частей (остальное игнорируется), иначе - перечисленные поля.

`<Имя>_Type` в `$select` на стенде 8.3.16 работает (проверено), хотя в ранних заметках встречалось обратное. Если на другой базе ответ «Сегмент пути X_Type не найден» - убери его из `$select`: свойство все равно приходит вместе с составным реквизитом.

## $expand (`--expand`)

Подставляет связанные сущности в ответ, чтобы не запрашивать каждую отдельно.

- `--expand Организация` - объект, на который ссылается реквизит.
- `--expand "Договор/Document_ДоговорНайма/Заявление"` - для составного реквизита после его имени указывается тип, затем реквизит; другой тип значения не раскрывается.
- `--expand "*"` - все навигационные ссылки. `Договор/*` для составного `Договор` без типа не поддерживается, `Договор/Document_ДоговорНайма/*` - поддерживается.
- Работает для `SliceLast()` и `SliceFirst()`; для виртуальных таблиц измерение раскрывается внутрь свойства, у составного - в свойство с суффиксом `_Expanded`.

Ограничения: не раскрываются реквизиты табличных частей; не поддерживается для одиночной сущности (`Catalog_X(guid'...')` с `$expand` - HTTP 501, «Опция $expand не поддерживается при запросе одиночных сущностей»). Для одного объекта запрашивай набор с `--filter "Ref_Key eq guid'...'"`.

Если нужно только наименование - `____Presentation` дешевле, чем `$expand`.

## $top, $skip (`--top`, `--skip`)

`$skip` применяется раньше `$top` независимо от порядка в URL. Без `$top` возвращается вся выборка.

## $orderby (`--orderby`)

Список через запятую, направление `asc` (по умолчанию) или `desc`: `--orderby "Date desc"`. Допускается путь к реквизиту связанной сущности: `Контрагент/ИНН asc`.

## $count (команда `count`)

`<ресурс>/$count?$filter=...` - в теле одно число.

## $inlinecount (`--inlinecount`)

`$inlinecount=allpages` добавляет в ответ общее количество по отбору (`odata.count`). Документация утверждает, что `$top` и `$skip` при этом игнорируются, но на стенде 8.3.16 `--inlinecount --top 1` вернул одну запись и полное количество - удобный способ узнать и количество, и пример записи одним запросом.

## allowedOnly (`--allowed-only`)

Только записи, разрешенные ограничением доступа (RLS). Без него попадание запрещенной записи в выборку дает ошибку прав. Только для GET к наборам.

## $format (`--meta`, `--xml`)

| Значение | Результат |
| --- | --- |
| `application/json;odata=nometadata` | json без служебных полей - по умолчанию в `odata.sh` |
| `application/json;odata=minimalmetadata` | `--meta minimal`: плюс `odata.metadata`, `@odata.type` и т. п. |
| `application/json;odata=fullmetadata` | `--meta full`: все служебные поля и навигационные ссылки |
| `atom` | `--xml`: atom-xml (формат по умолчанию у сервера, если `$format` не задан) |

## Описание сервиса

- Корень `standard.odata` - список опубликованных наборов (команда `sets`).
- `$metadata` - полное описание (CSDL, только XML): типы, ключи, свойства, функции. На крупной конфигурации - десятки МБ, поэтому читается только через `meta`.

## Данные «через точку»

К адресу одной сущности можно добавить путь по реквизитам через `/`: `Document_РасходТовара(guid'...')/Валюта/Description`. Стандартные реквизиты в пути - по-английски.
