# onec-odata

Skill для ИИ-агентов, устанавливаемый через [skills CLI](https://github.com/vercel-labs/skills):
чтение данных информационных баз 1С:Предприятия через стандартный интерфейс OData
(`standard.odata`), а по явному подтверждению пользователя - и их изменение.

## Возможности

- **Поиск и просмотр объектов**: документы, справочники, регистры с отбором по любым
  реквизитам; табличные части; наименования ссылок сразу в ответе, без отдельных запросов
  к справочникам.
- **Регистры**: движения документа по регистратору, остатки, обороты, срезы первых и
  последних (виртуальные таблицы).
- **Связи**: документы-основания и составные реквизиты, связанные объекты одним запросом
  (`$expand`).
- **Подсчеты**: количество записей и распределения по признаку без выгрузки данных.
- **Структура базы**: опубликованные объекты, ключи, реквизиты и параметры виртуальных
  таблиц конкретной базы; кеш описания обновляется сам при смене версии кода.
- **Ссылки на объекты**: навигационная ссылка 1С и ссылка веб-клиента; режим (никогда, по
  просьбе, всегда) задается в профиле.
- **Несколько баз**: профиль на каждую публикацию, у каждого разработчика свои профили вне git.
- **Безопасность**: по умолчанию только чтение; изменение данных - только с подтверждением
  пользователя на каждый запрос; профиль можно запретить для записи; пароль не попадает в
  команды, вывод и ссылки.
- **Защита от ложных выводов**: формы отбора, которые молча дают пустой результат,
  описаны и проверены на стендах; пустой ответ не считается доказательством отсутствия данных.

## Примеры запросов

Запросы агенту обычным языком; skill подключается сам.

- «Покажи последний проведенный документ ПеремещениеТоваров: склады и состав табличной части Товары»
- «Какие движения по регистру ТоварыНаСкладах сделал документ ПТ00000123 от 01.07.2025?»
- «Сколько заказов покупателя не проведено за сентябрь, в разбивке по организациям?»
- «Есть ли в базе документы, у которых заполнен реквизит ДокументОснование? Приведи примеры с типом основания»
- «Какой курс доллара действует на 01.10.2025?»
- «Найди три реальных элемента справочника Номенклатура с заполненным артикулом - нужны для фикстуры теста»
- «Какие реквизиты и табличные части есть у документа ЗаказПокупателя в этой базе?»
- «Покажи пять последних реализаций со ссылками на них»
- «Посмотри то же самое на базе test-stand» - переключение профиля по имени

## Как устроен

Skill дает агенту скрипт `odata.sh` (bash + curl) и справочники, собранные по
«Руководству разработчика» 1С:Предприятия (раздел «Стандартный интерфейс OData»,
редакции 8.3.16-8.3.27 и 8.5) и проверенные на рабочих стендах. Справочники
подгружаются в контекст по мере надобности, а не все сразу.

Что скрипт делает за агента:

- кодирует URL (кириллица, пробелы, `$`) - выражения передаются как есть;
- берет адрес и учетные данные из профиля, пароль не попадает в команду и вывод;
- показывает HTTP-код и текст ошибки сервера, а не «запрос не удался»;
- крупные ответы сохраняет в файл, в контекст попадает только начало;
- кеширует `$metadata` (десятки МБ) и выдает по нему ключи, реквизиты и функции
  виртуальных таблиц нужного типа;
- поддерживает все возможности интерфейса: `$expand`, представления, `$count`,
  `$inlinecount`, виртуальные таблицы регистров, `allowedOnly`.

## Требования

- `bash` и `curl`. В Linux и macOS они есть. На Windows Claude Code
  работает через Git Bash, в который входит `curl`.
- Сетевой доступ к веб-серверу с публикацией базы.

## Установка

```
skills add astrizhachuk/onec-odata -a claude-code -y
```

Глобально (для всех проектов) - с флагом `-g`. Под другого агента - замените
`claude-code` на нужное имя или укажите `-a '*'`.

### Windows

По умолчанию `skills` кладет файлы в общее хранилище `.agents/skills/`, а в
`.claude/skills/` ставит симлинк. Файловые инструменты Claude Code на Windows по
такому симлинку не проходят, поэтому и установка, и обновление - только с `--copy`:

```
skills add astrizhachuk/onec-odata -a claude-code --copy -y
```

`skills update` на Windows снова заменяет каталог симлинком. Для обновления
повторите команду выше. Если симлинк уже появился - удалите
`.claude/skills/onec-odata` и каталог `.agents/`, затем выполните команду.

## Обновление

skills update

## Профили подключения

Профиль - env-файл с параметрами одной базы. Основное место - каталог `.onec-odata/`
в корне репозитория проекта, **исключенный из git**: профиль лежит рядом с проектом,
но в коммиты не попадает, и у каждого разработчика свой.

```gitignore
# .gitignore проекта
/.onec-odata/
```

Профиль `-p ИМЯ` - файл `<корень git-репозитория текущего каталога>/.onec-odata/ИМЯ.env`,
поэтому скрипт запускается из каталога проекта. Файл в другом месте указывается явно: `-e ПУТЬ`.
Имя профиля - имя публикации (значение `ONEC_PUBLICATION`): `trade-test.env`.

Если файл профиля лежит в рабочем дереве git и не исключен из него, скрипт его не
прочитает и попросит добавить каталог в `.gitignore`: так пароль не уйдет в коммит.

Пример профиля:

```bash
ONEC_SERVER=http://web-server:90
ONEC_PUBLICATION=trade-test
ONEC_USER=odata
ONEC_PASSWORD=секрет
ONEC_READONLY=1
ONEC_OUT_DIR=C:/temp/onec-odata
ONEC_LINKS=on-request
ONEC_WEB_URL=http://web-server:90/trade-test/ru_RU
```

### Переменные профиля

| Переменная | Обязательная | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `ONEC_SERVER` | да | - | веб-сервер с портом: `http://web-server:90` |
| `ONEC_PUBLICATION` | да | - | имя публикации на веб-сервере, сегмент адреса: сервис - `<ONEC_SERVER>/<ONEC_PUBLICATION>/odata/standard.odata` |
| `ONEC_USER`, `ONEC_PASSWORD` | да | - | пользователь базы 1С; пароль передается curl через stdin и не попадает ни в командную строку, ни в вывод |
| `ONEC_TIMEOUT` | нет | `120` | таймаут одного запроса, с. Для разовой проверки медленной таблицы задается и переменной окружения при вызове: `ONEC_TIMEOUT=15 bash odata.sh ...` |
| `ONEC_READONLY` | нет | не задана | `1` - команда `write` отказывает: профиль только для чтения. Ставьте для промышленных баз и стендов, которые нельзя менять |
| `ONEC_OUT_DIR` | нет | `$TMPDIR/onec-odata` | каталог крупных ответов и кеша `$metadata` (см. «Каталог результатов») |
| `ONEC_LINKS` | нет | `on-request` | ссылки на объекты в ответах агента: `off` - никогда, `on-request` - только по просьбе пользователя и на объекты, измененные через `write`, `always` - на каждый объект в ответе |
| `ONEC_WEB_URL` | нет | не задана | адрес веб-клиента публикации: `<ONEC_SERVER>/<ONEC_PUBLICATION>/ru_RU`. Если задан, команда `link` дает кроме навигационной ссылки 1С еще и ссылку веб-клиента |

В Linux и macOS - права только владельцу: `chmod 600 .onec-odata/*.env`.

Какой профиль использовать в проекте, агент берет из CLAUDE.md проекта, например:

```markdown
Данные базы через OData - skill `onec-odata`, профиль по умолчанию `trade-test`.
```

### Ссылки на объекты

Команда `link НАБОР [GUID]` строит ссылки без обращения к серверу:

- навигационную ссылку 1С: `e1cib/data/Документ.ПеремещениеТоваров?ref=<32 hex>` - открывается в клиенте 1С через «Перейти по ссылке» (Shift+F11);
- при заданном `ONEC_WEB_URL` - ссылку веб-клиента `<ONEC_WEB_URL>/#e1cib/data/...` (первой строкой; кириллица не кодируется, чтобы ссылка была короткой и не рвалась при переносе строк).

В ответе агент дает одну ссылку на объект - ссылку веб-клиента с представлением объекта в тексте; навигационную ссылку 1С - только без веб-клиента или по просьбе.

Учетных данных в ссылках нет: при переходе клиент 1С запросит пользователя и пароль.

Ссылка на объект строится для справочников, документов, планов видов характеристик, счетов, видов расчета и обмена, бизнес-процессов и задач. Для регистров и журналов документов - только ссылка на список (`e1cib/list/...`), без GUID.

### Каталог результатов

Крупные ответы и кеш `$metadata` пишутся в каталог `ONEC_OUT_DIR` из профиля (по умолчанию
`$TMPDIR/onec-odata`, на Windows - системный temp). Кеш лежит в подкаталоге с именем профиля;
после изменения конфигурации базы обновляется командой `meta <Тип> --refresh`. Каталог можно
удалять целиком: кеш скачается заново при первом обращении (несколько секунд).

Чтобы кеш не устаревал после выкладок, skill принимает аргументом идентификатор снимка
метаданных (`argument-hint`) и передает его скрипту ключом `--snapshot-id`: идентификатор
сменился - кеш скачивается заново. Это непрозрачная строка, ее смысл задает проект (хеш
коммита, номер версии конфигурации и т. п.) и описывает в своем CLAUDE.md.

## Проверка

```bash
bash <каталог skill>/scripts/odata.sh -p trade-test info
```

Покажет адрес сервиса (без пароля) и число опубликованных наборов сущностей.

## Структура репозитория

Содержимое skill (`SKILL.md`, `scripts/`, `references/`) лежит в подкаталоге
`onec-odata/`, а не в корне репозитория: `SKILL.md` в корне включает в `skills` режим
установки, который копирует только сам `SKILL.md` без сопутствующих файлов.

`.gitattributes` закрепляет LF для `.sh`: со строками CRLF bash скрипт не выполнит.
